> 💬 **ELIZA Effect** : 단순한 패턴 매칭인데도 **사용자가 기계에 감정이나 지능이 있다고 착각**하는 현상 → 기술의 과대 평가로 이어짐
> (ELIZA는 환자의 말을 되묻거나 감정을 반영하는 **Rogerian 상담 방식**을 흉내 냈을 뿐)

## 4. Statistics vs ML — 가설을 '확인'하나, '발견'하나

> 분석 모델은 **전문가 직관을 기반으로 가설을 확인하는 통계분석**과, **데이터 관계를 학습하여 가설을 발견하는 머신러닝** 기법을 활용

| | **통계 분석** | **머신러닝 (+AI, +DL)** |
|---|---------------|-------------------------|
| **성격** | **가설 확인** 중심 | **가설 발견** 중심 |
| **접근** | **Human Driven Approach**<br>전문가의 과거 경험과 직관을 기반으로 가설 수립 후 모델 설계 | **Data Driven Approach**<br>데이터로부터 **인지하지 못했던 새로운 데이터·관계 발견** |
| **데이터** | **정형 데이터** (숫자), Sampling | **정형 + 비정형** (이미지, 텍스트 등), Big Data |
| **함수 모형** | 주로 **선형(Linear)** | **비선형(Non-Linear)** |

> 🎯 **강의의 강조점**
> **비교를 통한 우월함의 강조가 아니라, 발전의 방향과 영역의 확대**로 이해할 것.

### 방법론 관점 비교 (CRISP-DM 6단계 중 어디가 달라지나)

**공통 6단계** : ① 비즈니스 이해 → ② 가설 수립(Data Understanding) → ③ 데이터 준비 → ④ **분석 모델 정의(Modeling)** → ⑤ 모델 평가 → ⑥ 시스템 적용

| | **통계 기반** | **ML 기반** |
|---|---------------|-------------|
| **Data** | Sample Data | Data + **Feature Extraction & Selection** |
| **Modeling** | Linear Regression **또는** Logistic Regression<br>→ **(거의) 정해진 분석 기법**<br>• 회귀분석 : Linear<br>• 분류분석 : Logistic | **(A) Training, (B) Training, …** 여러 모델을 동시에 학습<br>각각 EDA를 거쳐 반복 |
| **Output** | Result | (A) Predict, (B) Predict, … → **Accuracy/Error 비교** → **Strong Model** 선택 |

> 💡 **가장 큰 차이** : 통계는 **기법이 먼저 정해져 있고**, ML은 **여러 후보를 돌려보고 가장 좋은 것을 고른다.**

### 모델링 관점 비교

| | **Statistic Modeling** | **Machine Learning** |
|---|------------------------|----------------------|
| **지향점** | 정해진 **분포와 가정에 부합하는 신뢰도 높은 모델**<br>→ 모델의 복잡성보다 **단순성** | **모델의 정확도** |
| **모델 형태** | **선형 방정식** 형태로 변수 간의 관계를 공식화<br>• 피팅 전에 **모델 곡선의 모양을 가정**해야 함<br>• 변수는 **해석 가능한 수준**으로 반영 | 규칙 기반이 아닌 **데이터에서 학습**할 수 있는 알고리즘 활용<br>학습 데이터 기반으로 패턴을 학습 → **기본적인 관계를 가정할 필요 없음** |
| **데이터 분할** | **Train : Test = 7 : 3**<br>Train에서 전체 정확도와 개별 변수 수준 진단 | **Train : Test = 7 : 3**, 그중 **Train = train : validation = 50 : 20**<br>Train으로 모델 개발 → **Validation으로 Hyperparameter 조정** 및 성능 검증 |
| **진단** | **P-value** 등 다양한 매개변수 진단 필요 | **통계적 진단 테스트를 수행하지 않음** |

## 5. 모델 접근 방향 — Classification vs Regression

| | 【 **Classification** 】 | 【 **Regression** 】 |
|---|--------------------------|----------------------|
| **목적** | 독립변수(X)로 답(Y)을 **구분하기 위한 경계 찾기**<br>➔ **Decision Boundary** | 독립변수(X)를 통해 답(Y)과 가장 유사하도록 **예측(Ŷ)**<br>➔ **Best Fit Line** |
| **결과값** | **Discrete** (이산형, 불연속)<br>➔ **Class Labels** | **Continuous** (연속형)<br>➔ **Number** |
| **모델 평가** | 분류 정확도<br>➔ **Accuracy** | 예측 정확도<br>➔ **Sum of Squared Error ($r^2$)** |

### 🔖 [참고] Which algorithm is good?

> 두 집단을 분류하는 Classifier를 고를 때 — **Case 1 / Case 2 / Case 3** 중 무엇이 정답일까?
>
> 💡 **답** : **데이터의 성격과 특징을 잘 반영한 결과를 보이는 알고리즘을 선택하는 것!!**
> (Consider the **conformability of the model structure with the data (shape)** — 모델 구조가 데이터의 모양과 얼마나 맞는지를 고려)
>
> → 전통적인 분류 모델 / Machine Learning Classification / Regularization Regression 중 **무엇이 우월한가**가 아니라, **이 데이터에 무엇이 맞는가**의 문제.

## 6. 모델 성능 영향 요인 — 노력의 85%는 모델링 이전에

> ⚠️ **전체 과정 중 모델링(알고리즘 적용) 전까지의 과정에 80~90% 노력이 필요함**

| Step | Task |
|------|------|
| **모델 설계**<br>(분석 요건 정의) | • Target / Feature 정의<br>• 분석 모집단 / 모델 Segmentation 정의<br>• 분석 방법론 선정 |
| **데이터 준비** | • 분석 Mart 설계<br>• 데이터 추출 / 정제 / 변환<br>• **Missing / Outlier 처리** |
| **분석 준비** | • 변수 변환 (표준화 / Grouping)<br>• Sampling (Random / Over sampling)<br>• Data Partition (Out of Data / Time) |
| **변수 탐색** | • **Feature Extraction** (파생변수)<br>• **변수 Selection** (안정성 / 예측력) |
| **Modeling** | • 알고리즘 적용 / 최적화<br>• 모델 평가 / 해석 |

**슬라이드에 표기된 Effort 비중** : 5% / 10% / 15% / 10% / 10% / **20%** / 15% / 15%
→ 가장 큰 몫이 **Feature Extraction(파생변수) 20%**, 그리고 **모델링 이전까지 누적 85%**, 크게는 **55% : 45%** 로 구분

> 🔑 **읽는 포인트** : 알고리즘을 바꾸는 것보다 **좋은 변수를 만드는 일(Feature Engineering)** 이 성능에 훨씬 크게 기여한다.

## 7. 🎓 당부 말씀 — 이 강의에서 가장 중요한 슬라이드

> **공모전이나 Kaggle에서는**
> 최대한 변수를 넣어 XGBoost/Ensemble 등으로 **최대의 성능을 획득**하는 접근 방식이 적합합니다. **목적이 우수한 모델 성능**이기 때문입니다.
>
> **비즈니스에서는**
> 목적에 맞고 **활용 가능한 데이터**를 확인하고, **안정적인 모델 성능**을 획득하는 것이 접근 방식입니다. **목적이 비즈니스 문제 해결**이기 때문입니다.
>
> ### 💡 비즈니스에서의 모델링은
> ### **성능 점수 싸움이 아니라, "현장의 문제 해결책 싸움"입니다.**
> **모델의 정확도보다 중요한 것은 현업이 그 결과를 이해하고, 수용하고, 활용할 수 있는가입니다.**

## 1. 용어의 이해 — 두 개의 고전적 정의

### 🅰 Arthur Samuel

> **"컴퓨터에게 명시적으로 프로그래밍하는 것 없이 배울 수 있는 능력을 주는 학문 분야"**
> *Machine Learning is the field of study that gives computers the ability to learn **without being explicitly programmed***

### 🅱 Tom M. Mitchell — **T, P, E 정의**

> **"컴퓨터 프로그램이 어떤 유형의 과업(T, Task)들에 대해 성과평가 지표(P, Performance measure)의 관점에서 경험(E, Experience)으로부터 배워서, 만약 성과평가 지표(P)의 값이 향상된다면 컴퓨터 프로그램은 학습을 할 수 있다고 말할 수 있다."**

| 기호 | 이름 | 강의에서 붙인 의미 |
|------|------|-------------------|
| **T** | Task | 무엇을 하는 일인가 |
| **P** | Performance measure | 잘하는지 재는 자 |
| **E** | Experience | **반복 시도 중 얻는 시행착오** / **모델링 전략** |

```
        Experience  ──►  Task  ──►  Performance
             ▲                            │
             └────────── Learning ────────┘
```

> 💡 **Improve with Experience** = **반복 시도 중 얻는 시행착오**
> → **Multi-run, Data-driven**
> ⚠️ 단, **Target(Label)이 사전에 확보되어 있어야 함** (지도학습의 전제)

## 2. Learning — 데이터셋을 어떻게 나누나 (Single-Split Evaluation)

```
Data Set (All)
   │
   ├──► Train Set ──┬──► Train Set ──────► ① Vanilla Model → Training Results
   │                │                          (R², RMSE, Accuracy, etc.)
   │                │
   │                └──► Validation Set ──► ② Validation Results
   │                                          → Hyperparameter tuning, model selection
   │
   └──► Test Set ────────────────────────► ③ Test Results
```

| # | 데이터셋 | 하는 일 | 결과 |
|---|----------|---------|------|
| **①** | **Train Set** | Vanilla Model 학습 | Training Results (R², RMSE, Accuracy 등) |
| **②** | **Validation Set** | **Hyperparameter tuning, model selection** | Validation Results |
| **③** | **Test Set** | 최종 성능 확인 | Test Results |

> 🎯 **하나의 모델을 만들고 Train–Valid–Test 성능을 비교하여 모델의 활용 여부를 확인** (**Single-Split Evaluation**)
>
> 💡 세 성능이 **비슷하게 유지되면 안정적**, Train만 높고 Valid/Test가 낮으면 **과적합**.

## 3. Machine Learning Type — 3가지 학습 유형

| 유형 | 데이터 조건 | Process | 설명 | Output |
|------|-------------|---------|------|--------|
| **Supervised Learning**<br>*(Task-driven)* | **All data is Labeled** | Model → Predict ↔ Label | • Input, Output 데이터 **모두 제공**<br>• 답(Y)을 찾기 위한 학습 (**감독학습**)<br>• 최적의 정확도를 보이는 모델로 **미래 데이터 예측** (Predict ⟷ Output 비교) | **Classification**<br>**Regression** |
| **Unsupervised Learning**<br>*(Data-oriented)* | **All data is Unlabeled** | Model → Predict | • **Input 데이터만 제공**<br>• 답(Y)을 알려주지 않은 상태 **또는** 답(Y)을 알지 못하는 상태에서 스스로 학습 (**자율학습**)<br>• 예상 패턴/clustering과 비교하여 **insight 도출** | **Clustering**<br>**Estimation / Dimension Reduction** |
| **Semi-Supervised Learning** | **Small portion Labeled**<br>**+ Lots of Unlabeled** | Model → Predict ↔ Label | • **Unlabeled 분포가 Labeled보다 더 많이 고려**됨<br>• Labeled 데이터로만 학습한 모델보다 **더 좋은 성능**의 모델을 만들어낼 가능성 있음<br>• Unlabeled를 함께 활용한다는 점에서 Supervised와 다르나 **Output은 동일** | **Classification**<br>**Regression** |

### 🔖 [참고] Semi-Supervised Learning 자세히

> 라벨링 작업에 어려움이 있거나 **학습 데이터량이 부족한 경우**, 지도학습과 비지도학습을 **함께 적용**하여 학습시키는 방법

**[배경]**
- **Labeled보다 Unlabeled 데이터를 확보하기 쉬움**
- Unlabeled를 학습에 사용하면 **데이터의 분포를 더 자세히 고려**할 수 있어, Labeled만으로 학습한 모델보다 더 좋은 성능을 낼 가능성 있음
- Label별 데이터 개수가 동일하다는 가정 하에, **Unlabeled를 함께 활용하면 성능이 향상되는 경향** 있음

**[가정사항]** — `X1(Labeled) — X2(Unlabeled) — X3(Unlabeled)`

| 가정 | 내용 |
|------|------|
| **Smoothness** | X1과 X3이 (직접) 가깝지 않더라도, **X3의 라벨이 X1과 같을 것이라는 기대**<br>💬 중간의 X2를 **징검다리 삼아 연결**되어 있다면 같은 라벨일 것이라는 뜻 |
| **Low-Density** | 라벨을 구분하는 **Optimal Boundary 주변에는 데이터가 적을 것**<br>💬 경계는 데이터가 **드문 골짜기**를 지나간다는 가정 |

## 1. ML Algorithm 지도 — 4개 계열

| 계열 | 키워드 | 알고리즘 | 특징 |

| 【 **CART** 】<br>*Classification and Regression Trees* | **Tree** | **Decision Tree** | • Decision Rule<br>• **트리 형태로 Rule 구분** |

### 🌳 CART 계열의 진화 — 왜 이 순서인가

**비유적 표현**
- 날씨가 좋으면 나간다 → 비가 오면 나가지 않는다
- 내일 우산을 챙길지 말지 어떻게 판단하나요? → 날씨를 본다, 예보를 본다, …

**데이터 기반**
- **조건 → 판단 → 결론**에 이르는 과정
- 사람이 정한 규칙이 아니라, **데이터에서 조건과 판단을 자동 생성**하여 결정

**알고리즘 확장**

| 단계 | 알고리즘 |
|------|----------|
| 트리 **하나** | **Decision Tree** |
| 트리 하나 → **트리 여러 개** | **randomForest** |
| 트리를 **하나씩 연결하여 오답을 줄이는 방향** | **Gradient Boosting** |
| **계산 속도, 정밀도까지 개선** | **XGBoost, LightGBM** |

## 2. Decision Tree (의사결정나무)

> 🎯 **나무 구조의 모형 기반으로 분류/예측하는 분석 방법**

- 의사결정나무, Decision Tree, DT, **CART**
- 의사결정규칙을 **도표화**하여 관심 대상 집단을 몇 개의 소집단으로 **분류(Classification)** 하거나 **예측(Prediction)** 하는 분석 방법
- 모델링 내용이 **나무구조로 한눈에 파악**되어 쉽게 이해하고 설명할 수 있음

### 활용 분야

| 구분 | 내용 |
|------|------|
| **분야** | 마케팅, CRM, 시장조사, 광고조사, 의학연구, 품질관리 |
| **주제** | 고객 신용점수, 캠페인 반응분석, **고객세분화**, 시장세분화, 광고효과측정, 자동차 잔가 예측 |

### 🔍 [Case] 고객세분화 — 트리로 **알 수 있는 것 / 없는 것**

| ✅ 해석할 수 있는 것 | ❌ 해석할 수 **없는** 것 |
|---------------------|------------------------|
| **분류 규칙(if-then)이 그대로 읽힌다**<br>(e.g.) 남성 + 월소득 500만원 이상 → Target **92%** | **세그먼트 규칙의 n수와 신뢰성은 모른다**<br>세그먼트별 %는 **비율**일 뿐 — 92%가 **몇 명**인지 알 수 없음 |
| **변수 중요도와 상호작용이 확인된다**<br>Root가 "성별"로 가장 중요한 변수. 남성은 소득, 여성은 신용도로 갈리는 특징 | **Target의 정의와 인과관계를 모른다**<br>트리는 **연관성만** 확인 가능 — **"남성이라서"라는 인과는 확인할 수 없음** |

> 🔑 **트리는 "무엇과 무엇이 같이 나타나는가"를 보여줄 뿐, "무엇이 무엇을 일으키는가"를 말해주지 않는다.**

## 3. 나무 형성의 원리 — 불순도(Impurity) 최소화

> 🎯 **Decision Tree의 나무 형성은 불순도가 최소화되는 방향으로 진행됨**

### 분리 기준

| 변수 유형 | 분리 방식 | 불순도 측정 |
|-----------|-----------|-------------|
| **연속형** | 분리기준보다 **작으면 왼쪽**, **크면 오른쪽** 자식 마디로<br>(예: `< 50` / `≥ 50`) | **분산** 활용 |
| **범주형** | 전체 범주를 **2개의 부분집합**으로 분리<br>(예: `{상}` / `{중, 하}`) | **카이제곱 통계량, 지니 지수(Gini Index), 엔트로피 지수(Information Theory)** |

### 나무 형성 과정

| 단계 | 내용 |
|------|------|
| **나무 성장 (Growing)** | 각 마디에서 **최적의 분리규칙**을 찾아서 나무를 성장. **정지규칙**을 만족하면 중단 |
| **정지규칙** | 더 이상 분리가 일어나지 않고 현재 자식마디가 **끝(leaf)이 되도록** 하는 규칙 |
| **가지치기 (Pruning)** | **오분류율을 크게 할 위험이 높거나 부적절한 추론규칙**을 가지고 있는 가지를 제거 |

### 📐 불순도 측정 2가지

> 어떤 변수를 기준으로 분할하면 **불순도가 가장 많이 낮아지는가**를 찾는 것이 핵심

**데이터 예시** : 총 10개 중 A 2개, B 3개, C 5개

#### ① Gini Index

$$Gini = 1 - \sum_{i=1}^{K} p_i^2 = 1 - \left[\left(\tfrac{2}{10}\right)^2 + \left(\tfrac{3}{10}\right)^2 + \left(\tfrac{5}{10}\right)^2\right] = 1 - (0.04 + 0.09 + 0.25) = \boldsymbol{0.62}$$

- 불순도를 측정하는 하나의 지수 (**0에 가까울수록 불순도 낮음**)
- 이 값을 참조하여 **불순도를 감소시켜주는 변수와 분류 방법**을 선택
- 의미 : **한 집단에서 임의로 두 개를 뽑았을 때 서로 다른 클래스가 나올 확률**

#### ② Entropy

$$Entropy = \sum_{i=1}^{K} -p_i \log_2 p_i = -\tfrac{2}{10}\log_2\tfrac{2}{10} - \tfrac{3}{10}\log_2\tfrac{3}{10} - \tfrac{5}{10}\log_2\tfrac{5}{10} = \boldsymbol{1.485}$$

- **{혼잡도, 자유도, 예측의 불확실성}** 을 측정하는 지표 (**0에 가까울수록 불순도 낮음**)
- 엔트로피가 **높을수록 많은 정보를 보유**하여 **불확실성이 높음**
- **로그**를 통해 정보량(불확실성)을 직접 측정 (서로 다른 사건의 **독립성** 반영)

### 🔖 [참고] Entropy 쉽게 이해하기 — "질문 몇 번 필요할까?"

> 빨간색 공과 파란색 공이 50개씩 있을 때

| 상황 | 순수도 | Entropy |
|------|--------|---------|
| 각 바구니에 **한 종류만** (전부 빨간색) | **완전히 순수** | **0** |
| **정확히 반반** (빨강 50, 파랑 50) | **가장 많이 섞임** | **최대** |

> **각 바구니에서 무작위로 하나 뽑았을 때 무슨 색인지 알려면, 질문이 평균 몇 번 필요할까?**
> - 전부 빨간색 → 물어볼 필요도 없음 = **0번** → entropy **0**
> - 색깔 반반 → 한 번은 꼭 물어봐야 함 = **1번** → entropy **1(bit)**
>
> 💡 **Entropy = 정답을 알아내는 데 드는 평균 질문 수 (불확실성)**
>
> 🌳 **의사결정나무에서 Entropy가 하는 일** : 분할 **전보다 분할 후에 entropy가 얼마나 줄어드는가**를 보고, **가장 많이 줄이는 분할**을 선택함

## 4. Feature Importance — 어떻게 계산되나

```
1번의 분할 기준 → entropy 감소량
        ↓ 특성별로 전부 합산
    Feature Importance
```

**고객세분화 예시로 읽기**

| 변수 | 왜 그만큼의 중요도가 나오나 |
|------|---------------------------|
| **성별** | root에서 1번 분할, **전체 샘플 대상** → **가중치 큼** |
| **월 소득** | 남성 그룹을 **92% vs 14%** 로 → 한 번의 분할로 크게 제거 |
| **신용도** | 여성 그룹을 좋음/나쁨으로 가름 (나쁨 2%, **거의 순수**) |
| **연령** | 여성 & 신용 좋음이라는 **하위 그룹에서만** → 샘플 비율 작아 **기여 작음** |

> ⚠️ **오해하기 쉬운 지점**
> Importance는 *"트리 위쪽에 있어서 매우 중요하다"* 라는 해석보다는
> ### **(Entropy를 얼마나 줄였나) × (몇 명에게 적용되나) 의 합**
> 으로 이해해야 합니다. (막대 길이 = 그 특성이 없앤 **Entropy 총량**)

## 5. Decision Tree의 장단점

| ✅ **Pros** | ❌ **Cons** |
|------------|------------|
| **직관적이고 이해하기 쉬움**<br>• 모델 시각화 가능, **비전문가도 이해**<br>• 규칙 기반 분류/예측, 결과 해석이 간단 | **과적합(Overfitting) 가능성**<br>• 나무가 **깊게 성장할수록** 훈련 데이터에 과적합<br>• 방지하려면 **가지치기(Pruning), 최대 깊이 제한** 필요 |
| **데이터 전처리 부담이 적음**<br>• 범주형·연속형 **모두 처리** 가능<br>• **표준화나 정규화 불필요**<br>• **이상치, 결측치에 덜 민감** | **불안정성**<br>• 데이터에 민감하여 **작은 변화에도 별도 트리 생성**<br>• 극복 위해 **앙상블 기법(RandomForest, Bagging)** 을 자주 사용 |
| **변수 중요도 파악 (Feature Importance)**<br>• 분할 기준으로 사용된 특성 기반으로 **중요 변수를 쉽게 파악** | **모델의 일반화 성능이 낮을 수 있음**<br>• 나무 깊이에 따라 일반화 성능 저하<br>• **단일 트리는 변수 간 상호작용 반영에 한계** |
| **작은 데이터셋에 적합**<br>• 비교적 작은 데이터셋에서도 잘 동작, **빠른 학습** | **데이터셋 영향**<br>• **큰 데이터셋**에서는 분할 기준 찾는 계산량 증가<br>• **클래스 불균형** 데이터에서 잘못된 분류 가능 (데이터 편향) |

## 6. 🔖 [참고] Overfitting — ML에서 반드시 고려해야 할 유일 포인트

**📖 사전적 의미**
- **Overfitting = Fit too much, 너무 잘 맞추다**
- Train dataset의 **노이즈나 특수한 패턴까지 학습**하여, test dataset 또는 production에서 성능 저하
- (e.g.) **모의고사 문제를 외워 100점**을 받았으나, **실전 수능에서 50점**

**🤖 모델 관점에서의 의미**
- Overfitting은 모델이 단순히 **데이터를 외운 상태**에 가까움
- **복잡한 모델 구조**(깊은 트리, 많은 파라미터)일수록 쉽게 발생
- **학습 데이터가 적을 때 / Feature 수가 많을 때 / Noise가 많을 때**도 발생 가능

**⚠️ 주의사항**
- ML 알고리즘은 성능을 올리기 위해 계속 학습하는 구조 → **기본적으로 overfitting 위험이 내재**
  ➔ **예외적인 문제가 아니라 기본적으로 항상 발생 가능성 있음**
- 반드시 **train – valid – test 성능을 비교**하여 안정적인 성능인지 확인

| 구분 | **정상적인 학습** | **Overfitting** |
|------|------------------|-----------------|
| **학습 대상** | 데이터의 **본질적 패턴** | 데이터의 **노이즈나 특수 상황**까지 반영 |
| **모델 복잡도** | 적절 : 규칙적 구조 | 과도 : 지나치게 복잡 |
| **검증 성능** | **안정적 유지** | 전반적으로 낮거나, 안정적으로 유지되지 못함 |

## 8. Boosting — `#tree #weak2strong`

> **Gradient Boosted Tree Machines**

| 키워드 | 하는 일 |
|--------|---------|
| **weak model** | 같은 가중치를 가지는 **여러 개의 성능이 낮은 모델**을 생성하고 |
| **gradient** | 낮은 성능을 높이기 위해 학습을 진행 (= **가중치 업데이트**), 샘플 데이터로 모델 성능을 fitting한 후 전체 학습데이터셋에 반영 |
| **boosting** | 해당 과정을 **반복하여 오차를 최소화**시키는 모델을 생성한다 |

> 🔑 **Random Forest vs Boosting**
> Random Forest는 **여러 트리를 동시에(병렬) 만들어 투표**, Boosting은 **트리를 순차적으로 이어 붙이며 이전 트리의 오답을 보완**.

### 부스팅 3형제 비교

| | **XGBoost**<br>*eXtreme Gradient Boosting* | **LightGBM** | **CatBoost** |
|---|---|---|---|
| **분할 방식** | **Depth-Wise** | **Leaf-Wise** | **Leaf-Wise + Ordered Boosting** |
| **특징** | 순차적으로 트리를 만들어 **이전 트리보다 더 나은 트리**를 생성<br>예측 성능이 좋은 편 | XGBoost의 연산방식 개선 (병렬처리)<br>**Leaf 중심으로 트리를 분할**<br>**XGBoost보다 빠르고 높은 정확도**를 보이는 경우가 많아짐 | **범주형 데이터를 전처리 없이 직접 처리** 가능<br>**튜닝 난이도가 낮고 기본 설정만으로도 높은 성능** → 현장에서 선호 |
| **잘 맞는 데이터** | 변수 종류가 많고 **데이터가 클수록** 상대적으로 뛰어난 성능 | 변수 종류가 많고 **데이터가 클수록** 상대적으로 뛰어난 성능 | 고유값이 많은 **범주형 변수**가 다수인 데이터 |
| **한계** | 복잡한 모델인 만큼 **모델 해석에 어려움** | — | — |

### 🔑 CatBoost의 Ordered Boosting — 왜 필요한가

**Boosting의 일반적 위험**
```
1. 이전 모델이 예측에 실패한 부분을
2. 다음 모델이 더 잘 맞추도록 보완하며
3. 반복해서 성능을 올림
   → 라벨을 너무 많이 참조하면서 학습하여 "정답을 외우는" 과적합 위험 증가
   → data leakage 위험
```

**Ordered Boosting의 해법**
- 학습데이터 내 **정답을 미리 다 보는 것이 아니라**
- **학습에 사용된 데이터만 기반으로** 다음 트리를 학습시켜 **과적합 방지**
- 💬 비유 : *같은 train 안에서도 **지금까지 풀어본 문제만 보고** 다음 문제를 풀도록 하는 방식*

```
[이미 본 데이터]  │  [아직 안 본 데이터]
                  ↑
        정답을 미리 다 보지 못하도록 막아둔 선
```

## 9. Support Vector Machine (SVM) — `#kernel #margin`

> 데이터를 2개 그룹으로 구분할 수 있는 **선형 분류를 먼저** 하고…

| 키워드 | 하는 일 |
|--------|---------|
| **maximum margin** | 그룹 간 분류를 좀 더 정확하게 하기 위해 **그룹 간 경계가 가장 큰 선형식**을 찾는다 |
| **kernel** | **선형으로 분류할 수 없는 경우 feature space를 변형**하여 그룹 간 경계가 가장 큰 선형식을 찾는다 |
| **soft margin** | 반복 수행하여 **경계는 크고, 분류 오류는 작은** 것들로 모델을 정의한다 |

### 🔤 Kernel 어원

| 관점 | 의미 |
|------|------|
| **용어** | 독일어 **"Kern"** 에서 유래 → 'core', 'essence' ➔ (사상·주체의) **핵심, 중심** |
| **수학** | 두 개체 사이의 **관계나 핵심적인 부분을 나타내는 함수** |

> 💡 **Kernel의 직관** : 지금 차원에서 직선으로 못 나누면, **차원을 올려서(feature space 변형)** 직선으로 나눌 수 있게 만든다.

### ⚙️ SVM 핵심 하이퍼파라미터 2개 — 둘 다 '모델 복잡도'를 조절

| 파라미터 | 정의 | 값이 클 때 | 값이 작을 때 |
|----------|------|-----------|-------------|
| **gamma** | 두 샘플 사이의 **거리에 얼마나 민감하게 반응할지** 결정<br>→ **경계의 복잡도** 조절 | 값(거리)에 **민감하게 반응**<br>→ **과적합 가능성 높아짐** | 경계가 완만해짐 |
| **C (Cost)** | **오차에 얼마나 벌점을 부과할지** 결정<br>→ **오분류를 얼마나 허용할 것인가**<br>*(Regularization parameter)* | **오분류를 최대한 줄이려는 방향**으로 학습<br>Margin이 좁아지고 데이터에 민감<br>→ **과적합(overfitting) 위험 ↑** | **Margin을 더 넓게** 잡아 벌점을 낮게 부여<br>"Training set에서 일부는 틀려도 괜찮다"<br>→ 많이 작으면 **과소적합(underfitting)** 가능 |

> 🔑 **gamma와 C를 함께 조절**하여 모델 최적화를 진행

## 10. Regularization (규제) — LASSO & Ridge

**📖 사전적 의미** : 규칙이나 표준에 맞춰 **정돈하다**
**= Regular(규칙, 기준, 일반) + -ization(과정 또는 결과)**

**🤖 Machine Learning에서**
- **목적** : 모델이 과도하게 복잡해져 **일반화 성능이 떨어지는 문제 완화**
- **방법** : 모델의 파라미터나 구조에 **인위적으로 제한(패널티)** 을 가하는 기법

| 효과 |
|------|
| **① Overfitting 방지** |
| **② 모델 복잡도 제어** |

**대표적인 방법 4가지**

| # | 방법 | 내용 |
|---|------|------|
| **1)** | **L2 Regularization (Ridge)** | **가중치 제곱합**에 대한 패널티 → **큰 가중치가 생성되지 못하도록** |
| **2)** | **L1 Regularization (Lasso)** | **가중치 절대값의 합**에 대한 패널티 → **특정 가중치를 0으로** 만들어 **변수 선택 효과** |
| **3)** | **Dropout** | (신경망) 뉴런 무작위 제거 |
| **4)** | **Batch Normalization** | (신경망) 각 층의 입력 정규화 |

### 🎤 [참고] L1/L2 쉽게 이해하기 — 발표자료 5장 제한

> **상황** : 발표를 위해 **30장의 슬라이드**를 준비했습니다. 내용은 많지만 **무슨 내용을 발표하려는지 잘 안 보입니다.**
> → 이게 바로 **과적합(Overfitting)** 상태 — 핵심이 안 보임/없음
>
> **교수님이 발표자료 제출은 5장으로 제한하셨습니다.** → 이것이 **Regularization (규칙 부여)**

| 줄이는 방식 | 대응 | 결과 |
|-------------|------|------|
| **모든 슬라이드를 조금씩 줄여서 정리** | **L2 Regularization (Ridge)** | 모든 가중치를 **균등하게 조절** → 변수는 **모두 반영**하되 전체 가중치를 줄이는 방향 |
| **필요 없는 슬라이드는 모두 삭제** | **L1 Regularization (LASSO)** | **일부 가중치를 0으로** 조절 → **변수 선택 효과** |

### 📊 LASSO vs Ridge 상세 비교

> ▪ 통계의 회귀분석으로 유효변수를 찾더라도, **높은 상관관계를 가진 변수** 때문에 설명력이 낮아질 수밖에 없음
> ▪ 모델이 너무 복잡해지는 것을 방지하고, 데이터의 **노이즈를 과도하게 학습하지 않도록**
> = 모델이 **일반화된 성능을 확보**할 수 있도록 = 모델 **예측력(설명력)이 높은** 모델 정의

| | **LASSO**<br>*Least Absolute Shrinkage and Selection Operator* | **Ridge**<br>*mountain crest, 능선/산등성이* |
|---|---|---|
| **규제** | **L1** — 회귀계수의 **절대값**에 패널티 | **L2** — 회귀계수의 **제곱합**에 패널티 |
| **계수 처리** | 낮은 회귀계수를 **강제로 "0"으로** 처리<br>→ **변수 선택 효과** 발생 | 회귀계수를 **표준화(center/scale)** 하고, 낮은 회귀계수는 **0에 가깝게(shrinkage)** 처리<br>→ **다중공선성 문제 완화** |
| **변수 반영** | 모델이 단순해지면 **중요한 변수만 남음** | **변수 선별 또는 제거 없이 처리된 변수를 모두 반영** |
| **alpha 시작값** | **0.1** 부터 시작 → *작은 alpha부터 시작해서 조심스럽게* | **1.0** 정도부터 시작 → *안정적으로* |
| **비유 (강의 예시)** | 유사한 의미를 가지는 단어를 **모두 없애고**, **"사랑한다"** 라는 단어만 채택<br>→ **모델 해석력 상승** | 관계 없는 데이터는 없애고 **유사한 의미는 최대한 반영**하여 **"사랑한다", "사모한다"** 를 함께 선택<br>→ 모델 복잡도가 상대적으로 있음 |
| **결과** | **계수가 0에 수렴** | **모두 0 근처로 수축** |
| **언제 쓰나** | **변수 선택 및 모델 단순화**가 필요할 때 | **다중공선성**이 우려되거나 **모든 변수를 활용**하고 싶을 때 |

> 💬 비유 문구만 보면 Ridge도 변수를 없애는 것처럼 읽히지만, **Ridge는 계수를 0에 "가깝게" 만들 뿐 정확히 0으로 만들지는 않습니다.** 표의 굵게 표시한 "**변수 선별 또는 제거 없이 모두 반영**"이 Ridge의 정확한 성질입니다. **정확히 0을 만드는 것은 LASSO뿐**입니다.

이름 그대로 **Cat**egorical Boosting — **범주형 데이터를 전처리 없이 직접 처리**할 수 있는 유일한 후보입니다. 튜닝 난이도도 낮아 현장에서 선호됩니다.
</details>

<details>
<summary><b>Q6.</b> 표본은 수백 개인데 <b>변수는 수천 개</b>인 데이터셋입니다 (유전자 발현, 텍스트 등). EDA를 통해 <b>비선형 경계</b>가 필요함을 확인했습니다.</summary>

**(A) Decision Tree / (B) Random Forest / (C) LightGBM / (D) SVM**

➡️ **정답 : (D) SVM**
두 조건이 모두 SVM을 가리킵니다.
① **비선형 경계** → **커널**로 feature space를 변형해 해결
② **표본 수 ≪ 변수 수 (p ≫ n)** → SVM은 **margin 최대화**로 이 상황에서 상대적으로 강건. 트리 계열은 샘플이 적으면 분할 기준 자체가 불안정해집니다.
</details>

<details>
<summary><b>Q7.</b> 변수가 수백 개인데 대체로 <b>선형 관계</b>입니다. <b>진짜 중요한 변수만 남긴 간결하고 해석 가능한</b> 모델이 필요합니다.</summary>

**(A) LASSO / (B) Ridge / (C) SVM / (D) LightGBM**

➡️ **정답 : (A) LASSO**
**"변수 선택"** 이 핵심 요구사항입니다. LASSO(L1)만이 **낮은 회귀계수를 강제로 0으로** 만들어 변수를 실제로 제거합니다.
B(Ridge)는 **모든 변수를 반영**하므로 "간결한 모델"이라는 조건에 맞지 않고, C·D는 선형 관계 데이터에 굳이 쓸 필요가 없으며 해석도 어렵습니다.
</details>

# 🧭 Part A 전체 흐름 한 장 요약

```
[문제] 규칙을 누가 만드는가?

   Rule by Human ────────────────► Rule by Machine
   (Rule-based, Statistics)        (Machine Learning)
   "길다+노란색 = 바나나"           데이터에서 스스로 규칙 발견
   가설 확인 (Human Driven)         가설 발견 (Data Driven)
   정형 데이터 / 선형                정형+비정형 / 비선형


[학습 방식]  T(Task) + P(Performance) + E(Experience) → Learning
   ├─ Supervised    : 전부 Labeled     → Classification / Regression
   ├─ Unsupervised  : 전부 Unlabeled   → Clustering / Dimension Reduction
   └─ Semi-Supervised : 일부만 Labeled → 라벨링 비용 절감 + 성능 향상 기대

[검증]  Data → Train / Validation / Test
        ①Train: 학습  ②Valid: 하이퍼파라미터 튜닝  ③Test: 최종 확인
        → 세 성능이 비슷해야 안정적 (Single-Split Evaluation)

[알고리즘 선택 지도]
   설명이 최우선            → Decision Tree
   안정성·무튜닝            → Random Forest      (병렬 + 투표)
   최고 정확도              → XGBoost            (순차 + 오답 보완, Depth-Wise)
   대용량·속도              → LightGBM           (Leaf-Wise)
   범주형 많음·전처리 최소   → CatBoost           (Ordered Boosting)
   비선형 경계 · p ≫ n      → SVM                (Kernel + Max Margin)
   선형 + 변수 선택 필요     → LASSO (L1)         계수를 0으로
   선형 + 다중공선성        → Ridge (L2)         계수를 0 근처로

[모든 알고리즘의 공통 적] → Overfitting
   대응 : Pruning / 앙상블 / Regularization / train-valid-test 비교

[가장 중요한 것] 노력의 85%는 모델링 이전 (특히 Feature Extraction 20%)
                 그리고 비즈니스에서는 "성능 점수 싸움이 아니라 문제 해결책 싸움"
```

## 🎓 시험/면접 대비 핵심 문답

| 질문 | 답 |
|------|-----|
| **AI, ML, DL의 관계는?** | ML은 **AI 연구 분야 중 하나**, DL은 그중 **인공신경망의 한계를 극복하기 위해 제안된 ML 방법 중 하나** (포함 관계) |
| **ELIZA와 Deep Blue의 공통 한계는?** | 둘 다 **규칙 기반**이며 **"학습과 일반화"를 하지 못함** |
| **ELIZA Effect란?** | 단순 패턴 매칭인데도 사용자가 **기계에 감정이나 지능이 있다고 착각**하는 현상 → 기술 과대평가 |
| **통계와 ML의 근본적 차이는?** | 통계 = **가설 확인** (Human Driven) / ML = **가설 발견** (Data Driven) |
| **ML의 데이터 분할 비율은?** | Train : Test = **7 : 3**, 그중 Train = train : validation = **50 : 20** |
| **통계는 P-value를 쓰는데 ML은?** | ML은 **통계적 진단 테스트를 수행하지 않음** |
| **Classification과 Regression의 평가지표는?** | Classification = **Accuracy** (Decision Boundary) / Regression = **SSE, r²** (Best Fit Line) |
| **Mitchell의 ML 정의 3요소는?** | **T**(Task), **P**(Performance measure), **E**(Experience) — E로부터 배워 P가 향상되면 학습한 것 |
| **Semi-Supervised의 두 가정은?** | **Smoothness**(가깝지 않아도 연결되면 같은 라벨) / **Low-Density**(최적 경계 주변에는 데이터가 적다) |
| **불순도 측정 지표 2가지는?** | **Gini Index**(임의로 둘 뽑았을 때 다른 클래스가 나올 확률) / **Entropy**(정답을 알아내는 데 드는 평균 질문 수) |
| **Entropy가 0 / 최대가 되는 때는?** | 한 종류만 있으면 **0**(완전 순수), 정확히 반반이면 **최대(1 bit)** |
| **트리는 분할 기준을 어떻게 고르나?** | 분할 **전보다 후에 불순도(entropy)가 가장 많이 줄어드는** 분할을 선택 |
| **Feature Importance의 정확한 의미는?** | "트리 위쪽이라 중요"가 아니라 **(Entropy를 얼마나 줄였나) × (몇 명에게 적용되나)의 합** |
| **Decision Tree로 인과관계를 알 수 있나?** | **없다.** 트리는 **연관성만** 확인 가능 |
| **Random Forest vs Boosting의 차이는?** | RF = 여러 트리를 **병렬로 만들어 투표(bagging)** / Boosting = **순차적으로 이어 붙이며 이전 트리의 오답을 보완** |
| **XGBoost와 LightGBM의 분할 방식은?** | XGBoost = **Depth-Wise** / LightGBM = **Leaf-Wise** (더 빠름) |
| **CatBoost의 Ordered Boosting은 왜?** | 정답을 미리 다 보면 **"정답을 외우는" 과적합(data leakage)** 위험 → **이미 본 데이터만으로** 다음 트리를 학습 |
| **SVM의 3요소는?** | **Maximum Margin**(경계를 가장 크게) + **Kernel**(비선형 시 feature space 변형) + **Soft Margin**(오류 일부 허용) |
| **SVM의 gamma와 C를 키우면?** | 둘 다 **과적합 위험 증가** — gamma↑ = 거리에 민감(경계 복잡), C↑ = 오분류를 최대한 줄이려 함(margin 좁아짐) |
| **LASSO와 Ridge의 결정적 차이는?** | LASSO(L1) = 계수를 **정확히 0으로** → **변수 선택** / Ridge(L2) = 계수를 **0 근처로만** → **모든 변수 반영**, 다중공선성 완화 |
| **alpha는 각각 얼마부터 시작?** | LASSO **0.1**, Ridge **1.0** |
| **Overfitting은 예외적 상황인가?** | **아니다.** ML은 성능을 올리려 계속 학습하므로 **기본적으로 항상 발생 가능** → 반드시 train-valid-test 비교 |
| **노력의 대부분은 어디에?** | **모델링 이전에 80~90%** (특히 Feature Extraction 20%) |
| **비즈니스 모델링의 판단 기준은?** | 정확도가 아니라 **현업이 결과를 이해하고, 수용하고, 활용할 수 있는가** |
