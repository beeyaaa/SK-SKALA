# CampusTask 요구사항

## 시스템 목적

학생의 강좌 수강정보와 강좌별 과제 및 제출 결과를 관리한다.

## 사용자

| 사용자 | 역할 |
|---|---|
| 학생 | 수강 강좌와 과제를 확인하고 과제를 제출한다. |
| 교수자 | 강좌에 과제를 등록하고 제출 결과를 확인·채점한다. |

사용자는 기능을 설명하기 위한 역할이며, 1일차에는 로그인과 권한을 구현하지 않는다.

## 기능 요구사항

| ID | 사용자 | 기능 | 요구사항 |
|---|---|---|---|
| REQ-01 | 교수자 | 학생 관리 | 학생의 학번, 이름, 이메일, 전화번호, 재학 여부를 관리한다. |
| REQ-02 | 교수자 | 강좌 관리 | 강좌 코드와 강좌명을 관리한다. |
| REQ-03 | 학생·교수자 | 수강신청 관리 | 학생과 강좌의 수강 관계를 등록하고 조회한다. |
| REQ-04 | 교수자 | 과제 관리 | 강좌별 과제 제목과 마감 일시를 등록한다. |
| REQ-05 | 학생 | 과제 제출 | 학생의 과제 제출 일시를 기록한다. |
| REQ-06 | 교수자 | 채점 | 제출물의 점수와 피드백을 기록한다. |
| REQ-07 | 학생·교수자 | 제출 결과 조회 | 제출 시간과 마감 시간을 비교하여 정상·지각 제출 여부를 조회한다. |

## 데이터 규칙

- 모든 테이블에는 기본키(PK)가 있어야 한다.
- 학번과 강좌 코드는 중복될 수 없다.
- 같은 학생과 강좌의 수강신청은 중복될 수 없다.
- 학생과 강좌의 N:M 관계는 `enrollments` 교차 테이블로 해소한다.
- 과제는 반드시 하나의 강좌에 소속된다.
- 제출물은 반드시 하나의 학생과 하나의 과제를 참조한다.
- 같은 학생은 같은 과제에 최종 제출물 한 건만 등록할 수 있다.
- 점수는 `NULL`이거나 0 이상 100 이하여야 한다.
- 전화번호와 피드백은 `NULL`을 허용한다.
- 각 테이블에는 샘플 데이터를 최소 10건 입력한다.

## 제외 범위

- 로그인과 사용자 권한
- 실제 파일 업로드
- 교수자 테이블
- 알림
- 팀 과제
- 재제출 이력
