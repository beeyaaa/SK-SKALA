# ML 모델 개발 및 최적화 - Day 1

> 좋은 모델을 어떻게 만들고, 올바르게 평가할 것인가?

## 한눈에 보는 핵심

이 자료의 핵심 메시지는 다음 한 문장으로 요약할 수 있다.

> **좋은 모델은 학습 데이터에만 잘 맞는 모델이 아니라, 보지 못한 데이터에도 안정적으로 작동하며 신뢰할 수 있는 방법으로 평가된 모델이다.**

이를 위해서는 알고리즘 선택만이 아니라 문제 정의, 데이터 품질, 피처 구성, 데이터 분할, 학습, 하이퍼파라미터 튜닝, 평가, 배포 후 모니터링까지 전체 워크플로를 함께 설계해야 한다.

핵심 흐름은 아래와 같다.

1. 비즈니스 문제와 예측 대상(Target)을 정의한다.
2. 데이터를 수집하고 정제하며 유용한 피처(Feature)를 만든다.
3. Train, Validation, Test 데이터의 역할을 분리한다.
4. 학습 데이터에서 입력과 출력 사이의 패턴을 학습한다.
5. 검증 데이터 또는 교차검증으로 모델과 하이퍼파라미터를 선택한다.
6. 테스트 데이터는 마지막에 한 번 사용하여 일반화 성능을 평가한다.
7. 문제의 목적과 오류 비용에 맞는 평가지표를 사용한다.
8. 성능이 비슷하다면 더 단순하고 강건한 모델을 우선 고려한다.

## 1. 왜 머신러닝을 사용하는가? (PDF p. 4-11)

### 규칙 기반 시스템의 한계

규칙 기반 시스템(Rule-based System)은 사람이 기준과 임계값을 직접 정한다.

예를 들어 대출 연체 위험을 판단할 때 다음과 같은 규칙을 만들 수 있다.

- 소득이 3,000만 원 미만이고 부채비율이 60%를 넘으면 위험
- 최근 6개월의 연체 횟수가 2회 이상이면 위험
- 월 상환액이 월 소득의 40%를 넘으면 위험

하지만 현실의 문제는 보통 하나의 조건만으로 설명되지 않는다. 변수의 수가 많고 변수들이 서로 상호작용하므로, 모든 경우를 사람이 규칙으로 작성하기 어렵다. 데이터가 추가되거나 환경이 변할 때마다 규칙을 수정해야 한다는 문제도 있다.

### 머신러닝의 역할

머신러닝은 사람이 모든 규칙을 직접 작성하는 대신, 데이터에서 입력과 출력 사이의 패턴을 학습한다.

```text
복잡한 문제 -> 데이터 -> 패턴 학습 -> 예측 또는 의사결정
```

- 학습 단계: `Data(X) + Output(y) -> Model`
- 추론 단계: `New Data + Model -> Prediction`

예를 들어 과거 고객의 소득, 부채, 거래 이력과 실제 연체 여부를 함께 제공하면 모델이 연체와 관련된 패턴을 학습하고 신규 고객의 연체 가능성을 예측한다.

다만 머신러닝이 사람의 판단 자체를 완전히 대체하는 것은 아니다. 분석가는 여전히 다음을 결정해야 한다.

- 어떤 데이터를 사용할 것인가?
- 무엇을 예측할 것인가?
- 어떤 모델을 사용할 것인가?
- 결과를 어떤 지표로 평가할 것인가?

### 모델은 현실의 근사(Approximation)다

모델은 현실을 완벽하게 복제하는 것이 아니라, 문제 해결에 유용한 패턴을 근사하고 새로운 사례에 일반화한다.

```text
Model = Approximation + Generalization
```

따라서 **좋은 모델은 완벽한 모델이 아니라, 실제 목적에 유용하게 일반화되는 모델**이다.

## 2. 머신러닝을 나누는 세 가지 관점 (PDF p. 12-22)

머신러닝은 다음 세 질문으로 분류하면 이해하기 쉽다.

1. **Learning Paradigm:** 어떻게 학습하는가?
2. **Prediction Task:** 무엇을 예측하는가?
3. **Model Family:** 어떤 구조의 모델을 사용하는가?

### 2.1 Learning Paradigm: 어떻게 학습하는가?

#### 지도학습(Supervised Learning)

입력 데이터와 함께 정답에 해당하는 레이블 또는 결과값이 제공된다. 모델은 입력과 정답의 관계를 학습하여 새로운 데이터의 결과를 예측한다.

- 대표 과제: Classification, Regression
- 예: 불량/정상 분류, 판매량 예측

#### 비지도학습(Unsupervised Learning)

정답 레이블 없이 데이터 자체의 구조와 패턴을 탐색한다.

- 대표 과제: Clustering, Dimensionality Reduction
- 예: 고객 군집화, 고차원 데이터 시각화

#### 준지도학습(Semi-supervised Learning)

소량의 레이블 데이터와 대량의 비레이블 데이터를 함께 사용한다. 의료, 자연어처리, 이미지 인식처럼 레이블링 비용이 큰 문제에서 유용하다.

일반적인 흐름은 다음과 같다.

1. 소량의 레이블 데이터로 초기 모델을 학습한다.
2. 초기 모델로 비레이블 데이터의 결과를 예측한다.
3. 레이블 데이터와 예측 정보를 함께 활용하여 모델을 개선한다.

### 2.2 Prediction Task: 무엇을 예측하는가?

#### 분류(Classification)

미리 정의된 범주(Class) 가운데 하나를 예측한다. 모델은 범주를 구분하는 결정 경계(Decision Boundary)를 학습한다.

- 이진 분류(Binary Classification): 불량/정상, 이탈/유지
- 다중 분류(Multi-class Classification): 여러 제품군 또는 질병 유형 분류

#### 회귀(Regression)

연속적인 수치값을 예측한다.

- 판매량, 가격, 수요, 온도, 제품 수명 예측
- 실제값과 예측값의 차이가 작아지도록 함수 또는 관계를 학습

> 주의: `Regression`은 문맥에 따라 연속값 예측이라는 **과제 유형**을 뜻하기도 하고, 선형 회귀 같은 **모델 계열**을 뜻하기도 한다.

### 2.3 Model Family: 어떤 모델 계열인가?

| 모델 계열 | 핵심 아이디어 | 대표 예시 | 주요 특징 |
|---|---|---|---|
| 선형 모델(Linear Models) | 입력과 출력의 관계를 선형 결합으로 표현 | Linear Regression, Logistic Regression | 빠르고 해석하기 쉬워 베이스라인으로 유용 |
| 사례 기반 모델(Instance-based Models) | 저장된 학습 사례와의 거리·유사도로 예측 | k-NN | 학습은 단순하지만 예측 비용이 커질 수 있음 |
| 확률·베이지안 모델 | 확률로 불확실성을 표현하고 사후확률을 갱신 | Naive Bayes, Bayesian Network | 불확실성 표현 가능, 복잡한 경우 근사 추론 필요 |
| 커널 기반 모델 | 커널을 이용해 비선형 패턴을 고차원 공간에서 분리 | SVM | 커널과 하이퍼파라미터 선택에 민감 |
| 트리 기반 모델 | 특성값을 기준으로 반복 분할 | CART, ID3 | 해석이 쉽지만 깊어지면 과적합 가능 |
| 앙상블 | 여러 모델의 결과를 결합 | Bagging, Boosting, Stacking | 분산이나 편향을 보완하고 안정성 향상 |
| 인공신경망 | 여러 뉴런과 층을 통해 복잡한 표현 학습 | Perceptron, MLP | 역전파와 경사하강법으로 학습 |
| 딥러닝 | 여러 은닉층으로 고차원·비정형 패턴 학습 | CNN, RNN, LSTM, Transformer | 이미지·텍스트·음성에 강하지만 많은 데이터와 계산 필요 |
| 군집화 | 유사한 샘플을 그룹으로 묶음 | k-Means, Hierarchical Clustering, DBSCAN | 레이블 없이 데이터 구조 탐색 |
| 차원 축소 | 핵심 정보를 유지하며 변수 수를 줄임 | PCA, t-SNE, UMAP | 시각화, 노이즈 제거, 후속 모델링에 활용 |

## 3. 모델 개발 워크플로 (PDF p. 23-29)

### 학습의 기본 구조

```text
Data -> Learning -> Model -> Prediction
```

- **Data:** 학습에 사용할 입력 `X`와 정답 `y`
- **Learning:** 데이터에서 패턴을 찾는 과정
- **Model:** 학습된 규칙과 관계
- **Prediction:** 새로운 데이터에 모델을 적용한 결과

모델의 학습은 다음 과정을 반복하며 예측 오차를 줄이는 일이다.

```text
Input X -> Model -> Prediction y_hat -> Compare with Actual y
        -> Error/Loss -> Update Model -> Repeat
```

즉, 학습은 **예측 오차를 줄이는 모델 파라미터를 찾는 과정**이다.

### 전체 개발 과정

```text
문제 정의
-> 데이터 수집
-> 피처 엔지니어링
-> 데이터 분할
-> 모델 학습
-> 평가 및 튜닝
-> 배포 및 모니터링
```

모델 성능은 학습 알고리즘 하나로 결정되지 않는다. 데이터 품질, 피처 구성, 분할 방식, 평가 방법이 함께 영향을 준다.

### 좋은 모델의 조건

좋은 모델은 다음 요소의 조합으로 만들어진다.

- 좋은 데이터와 적절한 데이터 분할
- 문제에 맞는 모델 선택과 학습
- 새로운 데이터에서의 일반화(Generalization)
- 적절한 평가지표를 통한 신뢰성 있는 평가
- 과소적합과 과적합을 피하는 적절한 복잡도

```text
Good Model = Good Fit + Good Generalization
```

학습 데이터의 성능은 출발점일 뿐이다. 처음 보는 데이터에서도 성능이 유지되어야 실제로 좋은 모델이다.

## 4. 데이터 분할과 재표본추출 (PDF p. 30-44)

### 4.1 Train, Validation, Test의 역할

| 데이터 | 용도 | 사용 시점 |
|---|---|---|
| Train Set | 모델 파라미터 학습 | 반복 사용 |
| Validation Set | 모델·하이퍼파라미터 선택 | 학습 및 튜닝 과정 |
| Test Set | 최종 일반화 성능 평가 | 모든 선택이 끝난 뒤 마지막에 사용 |

자료에서는 예시로 `Train : Validation : Test = 6 : 2 : 2`를 제시한다. 실제 비율은 데이터의 규모, 문제 특성, 시간 구조에 따라 달라질 수 있다.

중요한 원칙은 **Test Set을 학습이나 튜닝에 사용하지 않는 것**이다. 테스트 결과를 보고 모델을 반복 수정하면 테스트 데이터가 사실상 검증 데이터가 되어 최종 성능이 낙관적으로 편향된다.

전처리에서도 데이터 누수(Data Leakage)를 피해야 한다. 예를 들어 스케일러는 Train Set으로만 적합하고, 그 결과를 Validation/Test Set에 적용해야 한다.

### 4.2 Resampling, Sampling, Bootstrap

- **Sampling:** 모집단에서 일부 표본을 뽑아 모집단의 특성을 추론한다.
- **Resampling:** 보유한 데이터에서 반복적으로 표본을 다시 구성해 모델이나 통계량의 변동성을 평가한다.
- **Bootstrap:** 원본 데이터에서 복원추출(With Replacement)하여 여러 부트스트랩 샘플을 만든다. 통계량의 분포, 표준오차, 신뢰구간처럼 추정의 불확실성을 평가할 때 유용하다.

교차검증은 주로 “새 데이터에서도 잘 작동하는가?”를 평가하고 모델을 선택하는 데 쓰이며, 부트스트랩은 “추정값이 얼마나 불확실한가?”를 평가하는 데 자주 쓰인다.

### 4.3 홀드아웃 검증(Hold-out Validation)

데이터를 한 번만 Train/Validation으로 나누는 방식이다.

- 장점: 간단하고 계산 비용이 작다.
- 단점: 한 번의 우연한 분할에 결과가 크게 의존할 수 있다.
- 적합한 상황: 데이터가 충분히 많거나, 빠르게 베이스라인을 확인하는 초기 단계

### 4.4 교차검증(Cross-validation)

훈련 데이터를 여러 부분으로 나누어 Train과 Validation의 역할을 번갈아 수행한다. 각 검증 점수를 평균하면 단일 분할보다 안정적인 성능 추정치를 얻을 수 있다.

#### K-Fold Cross Validation

1. 데이터를 `K`개의 Fold로 나눈다.
2. 한 Fold를 Validation으로, 나머지 `K-1`개를 Train으로 사용한다.
3. 모든 Fold가 한 번씩 Validation이 되도록 `K`번 반복한다.
4. 각 성능지표의 평균을 최종 검증 성능으로 사용한다.

보통 `K=5` 또는 `K=10`을 많이 사용한다. 단일 홀드아웃보다 안정적이고 LOOCV보다 계산 비용이 낮다.

#### Stratified K-Fold Cross Validation

각 Fold가 전체 데이터와 비슷한 클래스 비율을 유지하도록 나누는 계층화 교차검증이다.

- 주로 분류 문제에서 사용
- 클래스 불균형(Class Imbalance)이 있을 때 특히 유용
- 클래스 구성 차이 때문에 평가가 왜곡되는 문제를 줄임

#### LOOCV(Leave-One-Out Cross Validation)

샘플 하나를 Validation으로 남기고 나머지 `n-1`개로 학습하는 과정을 모든 샘플에 대해 반복한다.

- 거의 전체 데이터를 학습에 사용하므로 학습 데이터 감소에 따른 편향이 작다.
- 무작위 분할에 따른 임의성이 없다.
- 모델을 `n`번 학습해야 하므로 계산 비용이 높다.
- 각 Validation Set이 샘플 하나뿐이어서 개별 평가의 분산이 클 수 있다.
- 데이터셋이 매우 작을 때 고려한다.

### 4.5 검증 방법 선택 가이드

| 상황 | 권장 방식 |
|---|---|
| 일반적인 회귀·분류 | K-Fold |
| 클래스가 불균형한 분류 | Stratified K-Fold |
| 데이터가 매우 작음 | LOOCV 고려 |
| 데이터가 충분히 많고 빠른 실험이 필요 | Hold-out |
| 시간 순서가 중요한 시계열 | 시간 순서를 보존한 분할 또는 시계열 교차검증 |

무작위 K-Fold가 항상 정답은 아니다. 시간에 따라 데이터 분포가 변하는 문제, 동일 고객·장비에서 여러 관측값이 나오는 문제에서는 시간 또는 그룹 단위의 분할을 고려해야 실제 배포 상황을 더 잘 재현할 수 있다.

## 5. 일반화, 과소적합, 과적합 (PDF p. 45-51)

### Learning과 Inference

- **Learning / Training / Fitting:** 정답 `Y`가 알려진 데이터로 모델을 만드는 과정
- **Inference:** 학습된 모델을 정답이 알려지지 않은 새로운 데이터에 적용하는 과정
- **Generalization:** 학습 데이터가 아닌 새로운 표본에도 학습한 관계가 적용되는 성질

### 모델 복잡도와 학습 곡선

모델 복잡도가 커지면 보통 훈련 오차는 계속 감소한다. 그러나 검증 오차는 어느 지점까지 감소한 뒤 다시 증가할 수 있다.

- 너무 단순한 모델: 훈련 데이터의 구조도 충분히 학습하지 못함
- 적절한 복잡도: 훈련 성능과 검증 성능이 균형을 이룸
- 지나치게 복잡한 모델: 훈련 데이터의 노이즈와 예외까지 학습함

### Bias-Variance Trade-off

- **High Bias:** 모델이 지나치게 단순해 실제 관계를 충분히 표현하지 못함 -> 과소적합(Underfitting)
- **High Variance:** 학습 샘플이 조금만 달라져도 모델 결과가 크게 변함 -> 과적합(Overfitting)

복잡도를 높이면 Bias는 감소하지만 Variance가 증가하기 쉽다. 교차검증은 이 균형이 가장 좋은 지점을 찾는 방법 중 하나이며, 정규화(Regularization), 부트스트래핑, 데이터 추가 등도 도움이 된다.

### 알고리즘 선택 원칙

- 성능이 비슷한 두 모델이 있다면 운영 효율성, 설명 가능성, 변수 수, 추론 비용을 고려해 더 단순한 모델을 우선 검토한다.
- 목표값의 활용 목적에 따라 사용할 수 있는 알고리즘과 지표가 달라진다.
- 여러 변수·모델 조합을 평가했는데도 성능이 낮다면 무작정 복잡도를 높이기보다 Target 정의와 Feature를 다시 검토한다.

자료는 모델링 이전 과정에 전체 노력의 80-90%가 필요하다는 점을 강조한다. 특히 문제와 Target 정의는 투입 시간보다 결과에 미치는 중요도가 크고, 데이터 준비는 가장 많은 실무 시간을 차지한다.

## 6. 회귀 모델 평가 (PDF p. 52-65)

### 평가지표 선택의 원칙

평가지표는 하나의 숫자가 아니라 “어떤 오류를 더 심각하게 볼 것인가?”라는 비즈니스 판단을 수학적으로 표현한 것이다.

- Target의 분포와 Scale을 확인한다.
- 이상치에 얼마나 민감해야 하는지 결정한다.
- 절대 오차와 비율 오차 중 어느 것이 더 의미 있는지 판단한다.
- 과대예측과 과소예측의 비용이 다른지 확인한다.
- 한 지표의 한계를 보완하기 위해 여러 지표를 함께 볼 수 있다.

### 6.1 MAE(Mean Absolute Error)

$$
MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
$$

- 실제값과 같은 단위를 사용해 직관적이다.
- 오차가 선형적으로 반영된다.
- MSE/RMSE보다 이상치에 덜 민감하다.
- Target의 Scale에 의존하므로 단위가 다른 문제를 직접 비교하기 어렵다.

### 6.2 MSE(Mean Squared Error)

$$
MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2
$$

- 큰 오차에 제곱 패널티를 부여하므로 이상치와 큰 실수를 강하게 반영한다.
- 단위가 제곱되어 원래 Target 단위로 해석하기 어렵다.
- 큰 오차가 특히 치명적인 문제에 적합하다.

### 6.3 RMSE(Root Mean Squared Error)

$$
RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}
$$

- MSE에 제곱근을 취해 Target과 단위를 같게 만든다.
- MAE보다 큰 오차를 더 강하게 벌점 처리한다.
- Scale에 의존한다.

### 6.4 MAPE(Mean Absolute Percentage Error)

$$
MAPE = \frac{100}{n}\sum_{i=1}^{n}\left|\frac{y_i-\hat{y}_i}{y_i}\right|
$$

- 오차를 백분율로 표현하여 직관적이다.
- Scale이 다른 대상 사이의 상대적 오차를 비교하기 쉽다.
- 실제값이 0이면 계산할 수 없다.
- 실제값이 0에 가까우면 비율이 과도하게 커져 지표가 왜곡된다.

`MPE(Mean Percentage Error)`는 부호가 있는 오차를 평균하므로 과대·과소예측 편향을 볼 수 있지만, 양수와 음수가 서로 상쇄될 수 있어 전체 오차 크기 평가에는 주의가 필요하다.

### 6.5 WAPE와 sMAPE

#### WAPE(Weighted Absolute Percentage Error)

$$
WAPE = \frac{\sum_i |y_i-\hat{y}_i|}{\sum_i |y_i|}\times100
$$

개별 실제값을 각각 분모로 쓰지 않고 전체 실제값 규모를 분모로 사용한다. 작은 실제값 하나가 전체 지표를 과도하게 왜곡하는 문제를 완화한다.

#### sMAPE(Symmetric Mean Absolute Percentage Error)

$$
sMAPE = \frac{100}{n}\sum_{i=1}^{n}
\frac{|y_i-\hat{y}_i|}{(|y_i|+|\hat{y}_i|)/2}
$$

실제값과 예측값의 평균 크기를 분모로 사용한다. MAPE의 비대칭성과 0 근처 왜곡을 완화하지만, 실제값과 예측값이 모두 0인 경우의 처리 규칙은 별도로 정해야 한다. 위 정의의 범위는 0-200%이며, 분모에서 2로 나누지 않는 정의는 0-100%가 된다.

### 6.6 결정계수(R-squared, $R^2$)

$$
R^2 = 1-\frac{SSE}{SST}
$$

- 회귀모델이 종속변수의 변동을 얼마나 설명하는지 나타내는 적합도(Goodness of Fit) 지표다.
- 예: `R² = 0.6`이면 모델이 결과변수 변동의 약 60%를 설명한다고 해석한다.
- 오차의 실제 크기를 알려주지는 않으므로 MAE나 RMSE와 함께 보는 것이 좋다.

> 보충: 절편을 포함한 동일 데이터의 일반적인 OLS 적합에서는 보통 0-1 범위지만, 테스트 데이터의 $R^2$ 또는 특정 설정에서는 음수가 될 수 있다. 음수라면 단순히 평균으로 예측하는 것보다도 성능이 낮다는 뜻이다.

### 6.7 업무 비용을 반영한 Custom Metric

모든 오차의 비용이 같은 것은 아니다. 예를 들어 고가 제품의 수요를 과소예측하면 결품이 발생하고, 과대예측하면 재고 과잉이 발생한다. 두 비용이 다르다면 과대·과소예측에 서로 다른 가중치를 주는 비대칭 손실함수를 설계할 수 있다.

## 7. 분류 모델 평가 (PDF p. 66-75)

### 임계값(Threshold)

분류모델은 보통 클래스 자체보다 양성일 확률을 출력한다. 이 확률이 특정 임계값 이상이면 Positive로 판정한다. 임계값을 바꾸면 Precision, Recall, TPR, FPR이 함께 변한다.

### 7.1 Confusion Matrix

|  | 실제 Positive | 실제 Negative |
|---|---:|---:|
| 예측 Positive | TP | FP |
| 예측 Negative | FN | TN |

- **TP(True Positive):** 실제 양성을 양성으로 예측
- **TN(True Negative):** 실제 음성을 음성으로 예측
- **FP(False Positive):** 실제 음성을 양성으로 잘못 예측, Type I Error
- **FN(False Negative):** 실제 양성을 음성으로 잘못 예측, Type II Error

### 7.2 Accuracy와 Error Rate

$$
Accuracy = \frac{TP+TN}{TP+FP+FN+TN}
$$

$$
Error\ Rate = \frac{FP+FN}{TP+FP+FN+TN}
$$

Accuracy는 클래스가 비교적 균형이고 FP와 FN의 비용이 비슷할 때 유용하다. 불균형 데이터에서는 심각하게 오해를 부를 수 있다.

예를 들어 정상 95명, 암환자 5명이 있는 데이터에서 모든 사람을 정상으로 예측하면 Accuracy는 95%지만 암환자를 한 명도 찾지 못한다. 따라서 높은 Accuracy만으로 좋은 분류모델이라고 판단할 수 없다.

### 7.3 Precision과 Recall

$$
Precision = \frac{TP}{TP+FP}
$$

모델이 Positive라고 예측한 것 가운데 실제 Positive의 비율이다. FP의 비용이 큰 문제에서 중요하다.

- 예: 금융사기 경보, 정상 거래를 사기로 잘못 차단하는 비용이 큰 경우

$$
Recall = Sensitivity = TPR = \frac{TP}{TP+FN}
$$

실제 Positive 가운데 모델이 찾아낸 비율이다. FN의 비용이 큰 문제에서 중요하다.

- 예: 질병 진단, 위험 설비 탐지

Precision과 Recall은 대체로 Trade-off 관계다. 확실한 경우만 Positive로 판정하면 Precision은 높아지지만 Recall이 낮아질 수 있고, 임계값을 낮춰 많은 사례를 Positive로 잡으면 Recall은 높아지지만 FP가 늘 수 있다.

### 7.4 Specificity와 Fall-out

$$
Specificity = \frac{TN}{TN+FP}
$$

실제 Negative 가운데 올바르게 Negative로 분류한 비율이다.

$$
Fallout = FPR = \frac{FP}{TN+FP} = 1-Specificity
$$

실제 Negative를 Positive로 잘못 분류한 비율이다.

### 7.5 F1 Score

$$
F1 = 2\times\frac{Precision\times Recall}{Precision+Recall}
$$

Precision과 Recall의 조화평균(Harmonic Mean)이다. 둘 중 하나가 매우 낮으면 F1도 크게 낮아지므로, 불균형 데이터에서 두 성능을 함께 확인할 때 유용하다.

단, F1은 TN을 직접 반영하지 않으며 FP와 FN의 비용을 동일하게 취급한다. 실제 업무에서 두 오류의 비용이 다르면 Precision, Recall 또는 가중 F-score를 따로 봐야 한다.

### 7.6 ROC Curve와 AUROC

ROC Curve는 임계값을 높은 값에서 낮은 값으로 이동시키며 다음 두 값을 그린 곡선이다.

- x축: FPR(False Positive Rate)
- y축: TPR(True Positive Rate) = Recall

좌상단에 가까운 곡선일수록 좋은 분류 성능을 의미한다. AUROC는 ROC 곡선 아래 면적을 하나의 값으로 요약한 것이다.

- `0.5`: 무작위 분류 수준
- `1.0`: 완벽한 분류
- 값이 클수록 양성과 음성을 순위상 잘 구분함

AUROC는 특정 임계값 하나에 고정되지 않은 전반적인 분리 능력을 보여준다. 다만 양성 클래스가 매우 희소할 때는 ROC-AUC가 낙관적으로 보일 수 있으므로 Precision-Recall Curve와 PR-AUC를 함께 확인하는 것이 좋다.

### 7.7 Log Loss

Log Loss는 정답을 맞혔는지만 보지 않고, 모델이 정답에 얼마나 높은 확률을 부여했는지 평가한다.

- 정답 클래스에 높은 확률을 주면 손실이 작다.
- 틀린 답에 강하게 확신하면 손실이 매우 커진다.
- 확률 예측의 품질과 Calibration이 중요한 문제에 적합하다.

이진 분류의 일반적인 식은 다음과 같다.

$$
LogLoss = -\frac{1}{n}\sum_{i=1}^{n}
[y_i\log(p_i)+(1-y_i)\log(1-p_i)]
$$

## 8. 왜 선형 모델은 여전히 중요한가? (PDF p. 76-77)

### 선형 모델은 단순한 직선 이상의 구조다

선형 회귀는 평균적인 관계와 오차 구조를 함께 표현한다.

$$
Y_i = \beta_0 + \beta_1X_i + \epsilon_i
$$

- `β0, β1`: 모집단의 평균적 관계를 나타내는 계수
- `εi`: 관측값마다 설명되지 않는 오차

표본에서 얻은 회귀선은 모집단의 관계를 추정한 것이다. 따라서 계수 자체뿐 아니라 오차에 관한 가정이 성립하는지도 확인해야 한다.

### 자료에서 다루는 주요 오차 가정

1. **오차의 평균이 0**

   $$E(\epsilon_i)=0$$

   평균적으로 과대예측과 과소예측이 한쪽으로 치우치지 않아야 한다.

2. **등분산성(Homoscedasticity)**

   $$Var(\epsilon_i)=\sigma^2$$

   `X`의 값에 관계없이 오차의 분산이 일정해야 한다. 오차 범위가 입력값에 따라 커지거나 작아지는 현상은 이분산성(Heteroscedasticity)이다.

3. **오차 간 비상관성**

   $$Cov(\epsilon_i,\epsilon_j)=0 \quad (i\neq j)$$

   서로 다른 관측치의 오차가 상관되지 않아야 한다. 시계열에서 오차가 연속적으로 비슷한 방향을 보이면 자기상관(Autocorrelation 또는 Serial Correlation)을 의심한다.

가정이 현실과 맞지 않으면 계수 추정과 불확실성 평가의 신뢰성이 떨어질 수 있다.

### 좋은 추정량

- **불편성(Unbiasedness):** 반복해서 표본을 뽑았을 때 추정량의 평균이 실제 모수와 일치한다.
- **낮은 분산(Low Variance):** 표본이 바뀌어도 추정값이 크게 흔들리지 않는다.

좋은 추정량은 Bias와 Variance를 함께 고려한다. 선형 회귀의 기울기 추정 분산은 직관적으로 다음 조건에서 작아진다.

- 샘플 수가 많을수록
- 오차 분산이 작을수록
- 설명변수 `X`가 충분히 넓은 범위에 퍼져 있을수록

### 복잡도와 강건성(Robustness)

강건성은 노이즈, 작은 입력 변화, 예상하지 못한 데이터 변화에도 예측 성능이 과도하게 흔들리지 않는 성질이다.

- 지나치게 복잡한 모델은 학습 데이터의 작은 변화에 민감해질 수 있다.
- 단순한 모델은 과적합 위험이 낮고 안정적인 일반화를 제공할 수 있다.
- 선형 모델은 구조가 단순하고 설명 가능성이 높아, 강건성과 해석 가능성이 중요한 업무에서 여전히 유용하다.

> **복잡한 모델이 항상 더 좋은 것은 아니다. 동일한 성능이라면 더 단순하고 안정적인 모델이 운영 환경에서 더 나을 수 있다.**

## 9. 평가 지표 빠른 선택표

### 회귀

| 상황 | 우선 검토할 지표 | 이유 |
|---|---|---|
| 평균적인 절대 오차를 원래 단위로 보고 싶음 | MAE | 직관적이고 이상치에 비교적 강함 |
| 큰 오차를 강하게 벌점 처리해야 함 | RMSE 또는 MSE | 제곱 패널티로 큰 오차 강조 |
| 규모가 다른 대상의 상대 오차를 비교 | MAPE | 백분율로 해석 가능 |
| 실제값이 0 또는 0 근처일 수 있음 | WAPE, sMAPE, MAE | MAPE의 0 분모 문제 완화 |
| 모델의 설명력을 확인 | R² + MAE/RMSE | 설명력과 실제 오차 크기를 함께 확인 |
| 과대·과소예측 비용이 다름 | Custom Metric | 업무 비용을 직접 반영 |

### 분류

| 상황 | 우선 검토할 지표 | 이유 |
|---|---|---|
| 클래스가 균형이고 오류 비용도 비슷함 | Accuracy | 전체 정답 비율이 의미 있음 |
| 거짓 경보(FP)가 비쌈 | Precision, Specificity | Positive 예측의 신뢰도와 음성 보호 |
| 놓침(FN)이 치명적임 | Recall/Sensitivity | 실제 양성을 최대한 탐지 |
| Precision과 Recall의 균형이 필요 | F1 Score | 두 지표의 조화평균 |
| 여러 임계값에서 전반적 분리 능력 비교 | ROC-AUC | Threshold-independent ranking 성능 |
| 양성 클래스가 매우 희소함 | PR Curve, PR-AUC | 희소 양성에 더 민감한 평가 |
| 확률의 신뢰도까지 평가 | Log Loss | 틀린 확신을 강하게 벌점 처리 |

## 용어 정리

| 용어 | 쉬운 설명 |
|---|---|
| Parameter | 학습 과정에서 데이터로부터 결정되는 모델 내부 값 |
| Hyperparameter | 사람이 설정하거나 검증으로 선택하는 학습 조건 |
| Loss Function | 학습 중 모델이 줄이려는 오차 함수 |
| Metric | 모델 성능을 해석하고 비교하기 위한 평가 기준 |
| Fit | 주어진 학습 데이터의 패턴을 얼마나 잘 설명하는지 |
| Generalization | 보지 못한 데이터에서도 성능이 유지되는 능력 |
| Underfitting | 모델이 너무 단순해 중요한 관계를 학습하지 못한 상태 |
| Overfitting | 학습 데이터의 노이즈와 예외까지 외워 일반화 성능이 떨어진 상태 |
| Bias | 모델의 가정이 단순해 발생하는 체계적인 오차 |
| Variance | 학습 데이터가 바뀔 때 모델 결과가 흔들리는 정도 |
| Robustness | 노이즈와 분포 변화에도 성능이 안정적인 정도 |
| Threshold | 확률 예측을 최종 클래스로 바꾸는 기준값 |
| Data Leakage | 학습 시점에 알 수 없어야 할 정보가 모델 또는 전처리에 유입되는 문제 |

## 최종 요약

1. 머신러닝은 사람이 모든 규칙을 작성하기 어려운 복잡한 문제에서 데이터로 패턴을 학습한다.
2. 모델은 현실의 완벽한 복제가 아니라 유용한 근사이며, 일반화가 핵심이다.
3. 좋은 성능은 알고리즘보다 전체 워크플로의 품질에 크게 좌우된다.
4. Train은 학습, Validation은 선택과 튜닝, Test는 최종 평가에 사용한다.
5. 교차검증은 단일 분할보다 안정적인 성능 추정을 제공한다.
6. 과소적합은 High Bias, 과적합은 High Variance와 연결된다.
7. 평가지표는 문제의 목적과 오류 비용에 맞게 선택해야 한다.
8. 불균형 분류에서는 Accuracy만 보면 안 되며 Precision, Recall, F1, PR-AUC 등을 함께 봐야 한다.
9. 회귀에서는 Scale, 이상치, 0 값, 과대·과소예측 비용을 고려해 MAE, RMSE, MAPE 계열을 선택한다.
10. 복잡한 모델이 항상 좋은 것은 아니며, 단순한 모델이 더 해석 가능하고 강건할 수 있다.
