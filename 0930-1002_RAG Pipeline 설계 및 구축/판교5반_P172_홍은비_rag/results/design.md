# 자동차보험 예시 약관 근거 검색: 종합실습 설계

## 1. 해결하려는 문제와 사용자

사고 검토 담당자가 약관 관련 질문을 할 때, 답에 필요한 **정확한 조항**을 찾아 그 근거와 함께 설명한다. 보험금·과실비율의 최종 판정은 범위 밖이다.

## 2. 문서와 데이터 범위

- 사용 문서: `data/Sample_Automobile_Insurance_Policy_Terms.pdf`
- 문서 성격: **실제 보험사 약관이 아닌 실습용 가상 약관**. PDF 첫 페이지에도 이를 명시한다.
- 범위: 약관 제1조~제17조. 판례·법률 PDF, 고객 CSV, 보험금 계산 모듈은 이번 검색 평가에서 사용하지 않는다.
- 전처리: PDF를 조항별로 분리하고 각 조항에 `article`, `article_title`, `pdf_page`, `source`를 기록한다.

**데이터 사용 내역:** 위 가상 약관 PDF 한 개만 RAG의 입력 문서로 사용했다. 제1조~제17조를 17개 문서·17개 청크로 색인하고, 같은 청크를 FAISS 의미 검색과 BM25 키워드 검색에 사용했다. 질문과 답변의 정답 근거도 이 PDF의 조항 번호와 본문으로 대조했다. 최초 평가 질문 10개와 추가 평가 질문 10개를 사용했으며, 고객 정보나 실제 보험사 자료는 입력·평가에 사용하지 않았다. PDF는 결과 재현을 돕기 위해 함께 보관했다. 데이터 파일을 제외하고 제출하는 경우에도 사용 범위는 이 문단에서 확인할 수 있으나, 코드를 다시 실행하려면 같은 PDF를 `data/`에 배치해야 한다.

## 3. RAG 구조

```text
약관 PDF → 조항별 로드 → RecursiveCharacterTextSplitter(400/40)
         → OpenAI text-embedding-3-small → FAISS
사용자 질문 → Retriever(Top-3) → 조항 번호·본문 → Prompt → gpt-4o-mini → 답변
```

기본 검색은 FAISS 유사도 검색이다. 가장 긴 조항도 346자라 `chunk_size=400`에서는 17개 조항이 각각 한 청크로 유지된다. 따라서 이번 자료에서 `chunk_overlap=40`은 실제로 쓰이지 않는다. 설정값 자체가 성능을 개선한 것으로 해석하지 않는다. 검색 결과와 답변에 조항 번호를 남겨 원문 확인이 가능하게 한다.

`Top-K=3`은 단일 조항 질문 7개와 두 조항이 필요한 복합 질문 2개를 모두 다루면서, 무관한 조항이 답변 문맥에 많이 들어오지 않도록 정한 실습용 값이다. Baseline과 Hybrid에 같은 값을 사용했다. K=1·5 등 다른 값과 비교해 최적화한 것은 아니다.

## 4. 개선 후보와 선택 근거

정확한 **조항 번호·금액·약관 용어**가 있는 질문과, 두 조항의 근거가 모두 필요한 질문을 평가에 포함했다. 유사도 검색이 이런 질문에서 필요한 조항을 놓치는지 먼저 살핀다. 코드에는 벡터 검색과 BM25의 상위 8개 결과를 순위 융합해 Top-3을 반환하는 Hybrid 후보를 준비했다. 두 검색기의 인덱스와 질문셋은 동일한 원문 조항을 사용한다.

실제 실행에서 Baseline은 Q1의 제10조와 Q4의 제12조를 놓쳤다. 두 질문은 자기부담금과 노후·부식처럼 약관에 명시된 용어가 중요하므로, 의미 유사도 검색에 BM25 키워드 검색을 더했다. 두 검색기의 상위 8개 결과를 역순위 점수로 합쳤을 때 두 조항이 Top-3에 들어왔고 나머지 7개 적중 질문도 유지했다. 질문별 결과와 답변 검토는 `evaluation.md`에 기록한다.

다른 방법도 선택 후보로 검토했다. MMR은 유사 청크 중복을 줄일 때 적합하지만, 이번 자료는 한 조항이 한 청크이고 Baseline의 핵심 문제는 필요한 조항 자체의 누락이었다. ParentDocumentRetriever는 작은 청크 때문에 문맥이 부족할 때 유용하지만, 현재는 조항 본문 전체가 한 청크에 들어 있다. Query Rewrite는 질문 표현이 다양한 경우, Reranker는 후보 안에 정답이 있으나 순서가 나쁜 경우에 고려할 수 있다. 이번에는 정확한 약관 용어를 보완하는 BM25가 관찰된 문제에 가장 직접적이라고 판단했다. 이 대안들은 실제 성능 비교를 실행하지 않았으므로 Hybrid가 모든 전략보다 낫다고 주장하지 않는다.

## 5. 평가 방법

- **질문셋:** 고정된 10개. 직접 질문, 표현을 바꾼 질문, 조항 번호 질문, 두 조항을 요구하는 복합 질문, 문서에 없는 질문을 포함한다.
- **정답 기준:** PDF 원문과 대조해 지정한 조항 번호. 단일 질문은 해당 조항, 복합 질문은 필요한 조항이 **모두** Top-3에 있어야 Hit이다. 제출 전 질문·정답 조항을 작성자가 최종 확인한다.
- **Retrieval Hit@3:** 답이 있는 9개 질문의 Hit 비율. 문서에 없는 Q10은 분모에서 제외한다.
- **Generation:** 기본·개선 검색이 가져온 동일한 질문별 문맥으로 답을 생성하고, 질문에 직접 답하는지, 원문과 일치하는지, 조항을 인용하는지 PDF 원문과 대조한다. Q10은 근거 없는 답을 만들지 않는지 따로 확인한다.
- **비교 조건:** PDF, 분할 설정, 임베딩 모델, Top-K, 답변 모델, 질문 순서를 고정하고 검색 방식만 바꾼다.

## 6. 한계

자료는 교육용 가상 약관 하나이며 17개 조항으로 작다. 이 질문셋의 결과를 실제 보험업무 성능으로 일반화할 수 없다. 조항 번호 포함 여부는 답변의 정확성 자체를 보장하지 않으므로 생성 답변은 원문과 대조했다. 한국어 BM25 토큰화는 단순 정규식 기반이다. 같은 질문셋을 보며 검색 방식과 프롬프트를 조정했으므로 전후 비교 결과는 독립 검증셋 성능이 아니다.

검색 설정과 프롬프트를 고정한 뒤 새 질문 10개로 한 차례 재평가했으며 결과는 `evaluation.md`에 기록했다. 다음 단계에서는 질문과 정답 조항을 제출자가 검토하고, 더 다양한 문서·질문으로 범위를 넓히며, 답변에 직접 쓰지 않은 조항이 인용되는 사례를 줄여야 한다.
