# Simple Agent 실습 가이드

## 목표

Tool(함수 호출) 기능을 기반으로 아주 단순한 Agent 2개를 직접 만들어본다.
여기서 "Agent"란 복잡한 프레임워크가 아니라 다음 3가지 요소의 조합으로 이해한다.

1. 역할을 정의하는 System Prompt
2. 그 역할 수행에 필요한 Tool(들)만 선택적으로 연결
3. 대화 상태를 유지하는 ChatClient

## 의존성 및 기반 구조

- Spring AI 2.0.0 기준으로 작성한다.
- `09.tools`의 코드 의존성(build 구성, `@Tool` 기반 함수 정의 방식)을 그대로 따른다.
- 화면 구조는 `09.tools`의 Thymeleaf 기반 단순 채팅 UI를 그대로 재사용한다.

## 핵심 구현 가이드

### 1. Tool 재사용

`09.tools`에 있는 `DateTimeTools`, `FileSystemTool`, `WeatherTools`를 그대로 가져와 사용한다.
기존 Tool을 Agent로 전환하는 방법을 실습한다. 

### 2. Agent 2개 정의

Agent마다 별도의 클래스(또는 빈)를 만들고, 그 안에서 아래를 함께 정의한다.

- 이 Agent의 역할을 설명하는 System Prompt
- 이 Agent에게만 필요한 Tool 목록 (전체 Tool을 다 묶지 않는다)
- 대화 이력 유지를 위한 `ChatMemory` 연동

두 Agent는 서로 다른 목적을 가지도록 구성한다. 하나는 파일 관련 작업(목록 조회/읽기 등)을,
다른 하나는 날씨 조회처럼 전혀 다른 영역을 다루게 하여 "Tool 세트가 Agent의 역량을 결정한다"는 점이 드러나야 한다.
구체적인 역할 문구, 시스템 프롬프트 표현, Tool 조합은 자유롭게 정해도 된다.


## 결과물 기준

아래 조건을 만족하면 실습이 완료된 것으로 본다.

1. 애플리케이션을 기동하면 채팅 화면에 Agent 선택용 select box(2개 옵션)가 보인다.
2. select box에서 Agent를 바꾸면 입력창의 추천 질문 문구도 함께 바뀐다.
3. "파일 관리" 계열 Agent를 선택해 추천 질문(또는 유사 질문)을 보내면, 실행 디렉토리의 파일 목록/내용을 Tool 호출을 통해 답변한다.
4. "날씨 안내" 계열 Agent를 선택해 도시명을 물으면, 날씨 Tool 호출 결과를 바탕으로 답변한다.
5. 같은 브라우저 세션 내에서는 이전 대화 맥락(ChatMemory)이 유지된다.
6. 두 Agent가 서로 다른 Tool 조합을 사용한다는 것이 코드상에서 명확히 구분되어 보인다.
